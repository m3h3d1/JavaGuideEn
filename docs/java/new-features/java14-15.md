JDK 14 was released on March 17, 2020. It was a non-LTS release.

### JEP 305: Pattern Matching for `instanceof` (Preview)

Java 14 continued to offer pattern matching for `instanceof` as a preview feature, first introduced in this release through JEP 305.

This feature combines an `instanceof` check with a type conversion, avoiding an explicit cast. Pattern matching for `instanceof` was previewed in Java 14 (JEP 305) and Java 15 (JEP 375), then became a permanent feature in Java 16 (JEP 394).

### JEP 358: Helpful NullPointerExceptions

Add the JVM option `-XX:+ShowCodeDetailsInExceptionMessages` to get more detail in NullPointerException messages and diagnose problems faster.

```java
a.b.c.i = 99; // Assume this line throws a NullPointerException.
```

Before Java 14:

```java
Exception in thread "main" java.lang.NullPointerException
    at NullPointerExample.main(NullPointerExample.java:5)
```

Starting in Java 14:

```java
 // With the option enabled, the message identifies which value is null.
Exception in thread "main" java.lang.NullPointerException:
        Cannot read field 'c' because 'a.b' is null.
    at Prog.main(Prog.java:5)
```

### JEP 361: Switch Expressions (Standard)

The `switch` expressions previewed in Java 12 became a permanent feature in Java 14. No option is needed to enable them.

Java 12 introduced arrow-style case labels, which do not require `break`. Java 13 added `yield` to return a value from a block in a `switch` expression.

```java
String result = switch (day) {
            case "M", "W", "F" -> "MWF";
            case "T", "TH", "S" -> "TTS";
            default -> {
                if(day.isEmpty())
                    yield "Please insert a valid day.";
                else
                    yield "Looks like a Sunday.";
            }

        };
System.out.println(result);
```

### JEP 359: Records (Preview)

The `record` keyword simplifies **data classes**, whose state cannot be changed after construction. Instead of declaring a class with fields and methods, you can declare a record's components and get accessor methods, `toString()`, `hashCode()`, and `equals()` automatically.

This is similar to declaring a class and using Lombok's `@Getter`, `@ToString`, and `@EqualsAndHashCode` annotations.

```java
/**
 * This class has two characteristics:
 * 1. All fields are final.
 * 2. It has a constructor and accessors for its two fields.
 * This kind of class is a good fit for a record.
 */
final class Rectangle implements Shape {
    final double length;
    final double width;

    public Rectangle(double length, double width) {
        this.length = length;
        this.width = width;
    }

    double length() { return length; }
    double width() { return width; }
}
/**
 * 1. A record automatically provides the three methods shown above.
 * 2. It also provides equals(), hashCode(), and toString().
 * 3. toString() includes the names and string representations of all components.
 */
record Rectangle(float length, float width) { }
```

### JEP 368: Text Blocks (Second Preview)

Text blocks remained a preview feature in Java 14, which added two escape sequences:

- `\`: Marks the end of a line without adding a newline.
- `\s`: Represents a single space.

```java
String str = "Java text blocks make multiline strings easier to read.";

String str2 = """
        Java text blocks make multiline strings \
        easier to read.""";
System.out.println(str2);// Java text blocks make multiline strings easier to read.
String text = """
        java
        c++\sphp
        """;
System.out.println(text);
// Output:
java
c++ php
```

### Other Features

- ZGC, introduced in Java 11, expanded beyond Linux to macOS and Windows in Java 14. This made it possible to try ZGC in everyday development environments, although G1 may already be sufficient for many use cases.
- [JEP 363: Remove the CMS Garbage Collector](https://openjdk.org/jeps/363)
- Java 14 added the `jpackage` tool. In addition to packaging applications as JAR files, it supports platform-specific packages such as `deb` and `rpm` on Linux and `msi` and `exe` on Windows.

### JEP 379: Shenandoah (Standard)

Shenandoah was introduced as an experimental collector in Java 12. After several releases of refinement, it became a standard feature in Java 15.

Shenandoah is a low-latency garbage collector led by Red Hat. Its main goals are:

- 99.9% of GC pauses under 10 ms
- Pause times independent of heap size
- Support for heaps ranging from a few hundred MB to several TB

Unlike G1 and ZGC, Shenandoah uses concurrent mark-compact and can perform garbage collection without stopping application threads.

Enable Shenandoah GC:

```bash
java -XX:+UseShenandoahGC className
```

### JEP 339: EdDSA

Java added a digital signature algorithm based on Edwards-Curve Digital Signature Algorithm (EdDSA), which offers improved security and performance.

Although it outperforms existing ECDSA implementations, EdDSA does not replace the JDK's existing Elliptic Curve Digital Signature Algorithm (ECDSA).

```java
KeyPairGenerator kpg = KeyPairGenerator.getInstance("Ed25519");
KeyPair kp = kpg.generateKeyPair();

byte[] msg = "test_string".getBytes(StandardCharsets.UTF_8);

Signature sig = Signature.getInstance("Ed25519");
sig.initSign(kp.getPrivate());
sig.update(msg);
byte[] s = sig.sign();

String encodedString = Base64.getEncoder().encodeToString(s);
System.out.println(encodedString);
```

Output:

```plain
0Hc0lxxASZNvS52WsvnncJOH/mlFhnA8Tc6D/k5DtAX5BSsNVjtPF4R4+yMWXVjrvB2mxVXmChIbki6goFBgAg==
```

### JEP 378: Text Blocks (Standard)

In Java 15, text blocks became a permanent feature and no longer required the `--enable-preview` option.

Text blocks provide a concise way to define multiline strings and are especially useful for SQL, JSON, and HTML.

### JEP 371: Hidden Classes

Hidden classes are designed for frameworks that generate classes dynamically. Other classes cannot use them directly in bytecode; they can be accessed indirectly at runtime through reflection.

Key characteristics:

- **Not discoverable:** Other classes cannot directly depend on hidden classes.
- **Short-lived:** They can be unloaded after use.
- **Performance:** They provide better support for dynamic language runtimes.

Use cases:

- Dynamic language runtimes such as JavaScript and Groovy
- Bytecode-generation frameworks such as ASM and CGLIB
- Reflection-based proxies, such as dynamic proxies

### JEP 360: Sealed Classes (Preview)

**Sealed classes** were introduced as a preview feature in Java 15.

Before sealed classes, you could use `final` to prevent a class from being extended. This was inflexible because it closed off inheritance entirely.

Sealed classes let you restrict which classes can extend or implement them.

```java
// Only Employee and Manager may extend the abstract Person class.
public abstract sealed class Person
    permits Employee, Manager {

    //...
}
```

Every class that extends a sealed class must itself be declared `sealed`, `non-sealed`, or `final`.

```java
public final class Employee extends Person {
}

public non-sealed class Manager extends Person {
}
```

![](https://oss.javaguide.cn/javaguide/image-20210820153955587.png)

If the permitted subclasses are in the same source file as the sealed class, the `permits` clause can be omitted. The compiler finds the subclasses in that file and adds them to the permitted list.

### JEP 375: Pattern Matching for `instanceof` (Second Preview)

Java 15 continued the preview of pattern matching for `instanceof` without major changes, allowing the team to gather more user feedback.

Pattern matching for `instanceof` binds a variable during the type check, avoiding an explicit cast and making code shorter and safer.

Example:

```java
// Traditional form
if (obj instanceof String) {
    String str = (String) obj;
    System.out.println(str.length());
}

// Pattern matching form
if (obj instanceof String str) {
    System.out.println(str.length());
}
```

### API Enhancements

#### CharSequence Enhancement

Before Java 15, checking whether a `StringBuilder`, `StringBuffer`, or `CharBuffer` was empty usually required calling `length() == 0`.

The `CharSequence` interface gained a default `isEmpty()` method, which returns `true` if the character sequence is empty.

```java
public interface CharSequence {
  default boolean isEmpty() {
      return this.length() == 0;
  }
}
```

Because `String`, `StringBuilder`, and other types implement this interface, you can now write these checks more consistently and clearly. This is especially useful in generic code that handles different character sequences.

**Note:** `String` already had an `isEmpty()` method. Java 15 added the capability to the interface so it is available through `CharSequence` as well.

#### TreeMap Performance Improvements

This is a low-level performance optimization. Methods such as `putIfAbsent()` and `compute()` were added to the `Map` interface in Java 8, but before Java 15, `TreeMap` inherited their default implementations.

**Java 15 change:** `TreeMap` overrides these methods:

- `putIfAbsent()`
- `computeIfAbsent()`
- `computeIfPresent()`
- `compute()`
- `merge()`

**Why override them?**

- **Performance:** The interface's default implementations may perform multiple lookups, such as checking whether a key exists before inserting it.
- **O(log n) complexity:** `TreeMap` can combine lookup and insertion in a single red-black tree traversal, avoiding repeated searches and improving performance on large data sets.
